# 第 20 课：TODO 清单系统——工具插件、事件驱动与持久化

## 本课定位

多步骤任务（如"重构整个模块"）需要 Agent 在开始前**列计划**、执行中**跟踪进度**、完成后**总结**。如果没有计划跟踪，Agent 容易在长任务中迷失方向——"我做到哪一步了？还有哪些没做？"

本课实现 `todo_write` 工具（对齐 Claude Code 的 TodoWrite 模式）：Agent 在任务开始时列出计划（每项带 `pending/in_progress/completed` 状态），每完成一步更新状态，前端「TODOs」面板实时同步。任务结束后看板保留，用户可查看历史。

## 一、ToolPlugin 完整生命周期

在深入 `todo_write` 之前，先回顾 `ToolPlugin` 的完整生命周期：

```
安装阶段（一次）
  install(kernel)
    → 注册服务到 kernel
    → 获取 kernel 上其他服务（依赖注入）

注册阶段（每次任务）
  get_tools()
    → 返回 ToolDefinition 列表
    → 被 ToolRegistry 收集，供 Agent 裁剪

执行阶段（多次）
  execute(name, args)
    → 被 AgentLoop 调用
    → 返回字符串结果
```

`TodoPlugin` 遵循这个模式：

```python
# todos.py（核心）
class TodoPlugin(ToolPlugin):
    name = "todo-plugin"

    def install(self, kernel):
        # 注册服务：让其他组件可以访问看板（如 TaskManager 调用 bind/unbind）
        super().install(kernel)
        kernel.register_service("todo_plugin", self)

    def get_tools(self):
        return [ToolDefinition(name="todo_write", ...)]

    async def execute(self, name, args):
        # 校验 → 存储 → 推送 → 返回
        ...
```

## 二、todo_write 工具设计

### 2.1 全量覆盖式

`todo_write` 每次提交**完整清单**（不是增量追加）。这样做的好处：

1. **幂等**：LLM 不需要记住"之前的状态是什么"，只需要写出当前完整状态；
2. **容错**：如果某次更新丢失了某项（LLM 忘记写了），下次更新时会补上；
3. **简单**：服务端不需要 diff 逻辑，全量替换即可。

### 2.2 校验

```python
# todos.py（核心）
VALID_STATUSES = ("pending", "in_progress", "completed")
MAX_TODOS = 100

async def execute(self, name, args):
    session_id = current_session_id.get("")
    if not session_id:
        return "[Error] 当前没有活动会话"

    todos = args.get("todos")
    if not isinstance(todos, list):
        return "[Error] todos 必须是数组"

    cleaned = []
    for i, item in enumerate(todos):
        content = str(item.get("content", "")).strip()
        status = str(item.get("status", "pending")).strip()
        if not content:
            return f"[Error] 第 {i + 1} 项 content 不能为空"
        if status not in VALID_STATUSES:
            return f"[Error] 第 {i + 1} 项 status 非法: {status}"

        cleaned.append({"content": content, "status": status})

    self._items[session_id] = cleaned
    ...
```

校验规则：三项必检——① `todos` 是数组；② 每项 `content` 非空；③ 每项 `status` 在 `(pending/in_progress/completed)` 中。任何一项不通过，返回错误文本让 LLM 自愈。

### 2.3 渲染板面

工具执行结果返回带进度统计的文本板面：

```python
# todos.py（核心）
_STATUS_MARKS = {"pending": "☐", "in_progress": "▶", "completed": "✔"}

def _render_board(todos):
    return "\n".join(f"{_STATUS_MARKS[t['status']]} {t['content']}" for t in todos)

# 在 execute 最后：
done = sum(1 for t in cleaned if t["status"] == "completed")
doing = sum(1 for t in cleaned if t["status"] == "in_progress")
header = f"TODO 清单已更新：共 {len(cleaned)} 项（✔{done} ▶{doing} ☐{len(cleaned)-done-doing}）"
return f"{header}\n{_render_board(cleaned)}"
```

Agent 拿到这个结果后，可以直观看到当前进度，下次更新时据此调整。

## 三、事件驱动实时推送

### 3.1 ContextVar 传递 session_id

`todo_write` 需要知道"当前是哪个会话"才能正确存储和推送。通过 `ContextVar` 传递：

```python
# todos.py（核心）
current_session_id: contextvars.ContextVar = contextvars.ContextVar(
    "current_session_id", default=""
)
```

在 `AgentLoop.run_task` 启动时设置：

```python
# agent_loop.py（核心）
current_session_id.set(self.kernel.session_id)
```

`ContextVar` 是 Python 3.7+ 的线程/协程本地变量。同一协程内读写可靠，**并行协程各自独立**——这保证了工具并行化时不会串会话。

### 3.2 todo:updated 事件

每次 `todo_write` 执行后，通过事件总线广播 `todo:updated`：

```python
# todos.py（核心）
events = self._events.get(session_id)
if events is not None:
    await events.emit("todo:updated", {"todos": list(cleaned)})
```

前端收到后更新「TODOs」面板：

```typescript
case "todo:updated":
  setTodos(ev.data.todos);
```

### 3.3 TaskManager 绑定/解绑时机

`TaskManager` 在任务启动时调用 `bind`，结束时调用 `unbind`：

```python
# tasks.py（核心）
class TaskManager:
    def start(self, session_id, ...):
        # 绑定 TODO 看板到会话事件总线
        if self.app.todo_plugin:
            self.app.todo_plugin.bind(session_id, kernel.events)

    async def stop(self, task_id):
        # 解绑 TODO 看板（任务结束，不再推送事件）
        handle = self._running.pop(task_id, None)
        if handle and self.app.todo_plugin:
            self.app.todo_plugin.unbind(handle.session_id)
```

`bind` 时如果内存未命中，从磁盘恢复看板（断连后重连可以恢复进度）。

## 四、看板持久化

### 4.1 原子写入

每次 `todo_write` 同步落盘，使用**临时文件 + rename** 原子写入：

```python
# todos.py（核心）
def _persist(self, session_id, todos):
    path = self._board_path(session_id)
    if path is None:
        return
    os.makedirs(os.path.dirname(path), exist_ok=True)
    tmp = f"{path}.tmp"
    with open(tmp, "w", encoding="utf-8") as f:
        json.dump({"session_id": session_id, "todos": todos, ...}, f)
    os.replace(tmp, path)  # 原子替换
```

`os.replace` 是原子的——如果写临时文件时进程崩溃，.tmp 文件不会影响已有的 .json 文件。

### 4.2 内存命中优先 + 磁盘恢复

读取策略：内存命中优先，未命中回退磁盘：

```python
def get(self, session_id):
    if session_id in self._items:
        return list(self._items[session_id])
    disk = self._load_disk(session_id)
    if disk:
        self._items[session_id] = disk
    return list(disk)
```

这样页面刷新或服务重启后，看板数据自动恢复。

### 4.3 会话删除时清理

会话删除时同步清理看板：

```python
def delete_board(self, session_id):
    self._items.pop(session_id, None)
    self._events.pop(session_id, None)
    path = self._board_path(session_id)
    if path and os.path.isfile(path):
        os.remove(path)
```

## 五、前端 TODOs 面板

前端「TODOs」面板显示当前会话的进度：

```
┌─ TODOs ────────────────────────┐
│ 共 5 项（✔3 ▶1 ☐1）           │
│                                │
│ ✔ 分析现有代码结构             │
│ ✔ 设计新架构方案               │
│ ✔ 重构核心模块                 │
│ ▶ 更新相关测试                 │  ← 高亮（in_progress）
│ ☐ 更新 README 文档             │
└────────────────────────────────┘
```

关键设计：

- **进度统计**：统计总量和各类状态数量；
- **in_progress 高亮**：当前进行中的项用不同颜色标出，一目了然；
- **任务结束保留**：任务结束后看板不消失，用户可以回顾历史任务的完成情况。

## 六、与 AgentLoop 的绑定/解绑时机

```
任务启动（TaskManager.start）
  → TodoPlugin.bind(session_id, kernel.events)
    → 内存未命中？从磁盘恢复
    → 后续 todo_write 通过 events 推送 todo:updated

任务运行中
  → Agent 每次调用 todo_write 更新清单
  → 同步落盘 + 事件推送

任务结束（TaskManager.stop）
  → TodoPlugin.unbind(session_id)
    → 停止事件推送
    → 看板保留在内存 + 磁盘（下次 bind 时恢复）
```

## 本课小结

1. **ToolPlugin 生命周期**：`install → get_tools → execute` 三步走；
2. **todo_write 全量覆盖**：幂等、容错、简单；校验内容/状态/数量三重防线；
3. **事件驱动实时推送**：`ContextVar` 传递 session_id，`todo:updated` 事件推送到前端 TODOs 面板；
4. **持久化**：原子写入 + 内存命中优先 + 磁盘恢复 + 会话删除清理；
5. **绑定/解绑**：`TaskManager` 在任务开始/结束时调用 `bind/unbind`。
