在第十二课中，我们实现了基石级的 **Cordis 插件内核** 与 **Trajectory 轨迹记录服务**。但仅仅支持"事件监听（EventBus）"还不够：
1. **无法干预执行流**：EventBus 是单向异步通知，插件只能"看"无法"改"；
2. **缺乏前置校验与安全防线**：在 Tool 正式执行前，如果插件想要拦截高危指令（如 `git push -f`），必须有一种能**中断（Abort）或改写（Mutate）** 流程的机制。

本课我们将引入 **洋葱模型中间件（Interceptor / Pipeline）** 与 **全生命周期钩子（Lifecycle Hooks）**，让 Harness 具备在运行期**无感修改 Prompt**、**拦截 Tool 执行**以及**错误优雅熔断**的能力。

#### 1. 洋葱模型与 Hook 生命周期全景

一个完整请求循环的生命周期 Hook 拓扑图如下：

```text
[User Prompt]
     │
     ▼
┌────────────────────────────────────────────────────────┐
│  onBeforeLLM (中间件 pipeline: 修改 Prompt / 补充 Memory) │
└───────────────────────────┬────────────────────────────┘
                            │
                            ▼
                    ┌──────────────┐
                    │ LLM Stream   │
                    └───────┬──────┘
                            │
                            ▼
┌────────────────────────────────────────────────────────┐
│  onToolExecute (中间件 pipeline: 安全审查 / 权限判决)    │
└───────────────────────────┬────────────────────────────┘
                            │
               ┌────────────┴────────────┐
               │                         │
               ▼ (Approved)              ▼ (Rejected)
       ┌──────────────┐          ┌──────────────┐
       │ Execute Tool │          │ Blocked Error│
       └───────┬──────┘          └───────┬──────┘
               │                         │
               └────────────┬────────────┘
                            │
                            ▼
┌────────────────────────────────────────────────────────┐
│  onAfterTool (中间件 pipeline: 结果截断 / 格式化修饰)    │
└────────────────────────────────────────────────────────┘
```

#### 2. 设计 Interceptor Pipeline（拦截器管道）

我们编写一个支持洋葱模型的 `Pipeline`，每个中间件可以自由决定是否调用 `next()` 继续（对应 `litecode/core/pipeline.py` 的真实实现）：

```python
# core/pipeline.py
import asyncio
from typing import Any, Callable, List

class Pipeline:
    """洋葱模型管道：每个中间件可决定是否调用 next() 继续向下流转。"""

    def __init__(self, name: str = "pipeline"):
        self.name = name
        self._middlewares: List[Callable] = []

    def use(self, middleware: Callable) -> None:
        self._middlewares.append(middleware)

    async def run(self, ctx: Context, initial_data: Any) -> Any:
        async def dispatch(index: int, data: Any) -> Any:
            if index >= len(self._middlewares):
                return data
            fn = self._middlewares[index]

            async def next_call(next_data: Any = None) -> Any:
                return await dispatch(index + 1,
                                      next_data if next_data is not None else data)

            result = fn(ctx, data, next_call)
            if asyncio.iscoroutine(result):
                result = await result
            return result

        return await dispatch(0, initial_data)
```

中间件签名固定为 `(ctx, data, next)`，`next(data)` 向下传递，返回 `data` 给上层——这就是洋葱模型的核心：请求进入 → 逐层预处理 → 核心处理 → 逐层返回修饰。

#### 3. 增强 Kernel：支持 Hook 阶段挂载

修改 Kernel，将 `Pipeline` 挂载到关键的生命周期阶段：

```python
# core/kernel.py（扩展版）
class Kernel:
    def __init__(self, session_id: str):
        self.events = TypedEventBus()
        self.ctx = Context(session_id=session_id)
        # 三个核心阶段的拦截器管道
        self.before_llm = Pipeline("before_llm")       # LLM 调用前
        self.before_tool = Pipeline("before_tool")     # 工具执行前
        self.after_tool = Pipeline("after_tool")       # 工具执行后
        self._plugins = {}

    def use(self, plugin: Plugin) -> "Kernel":
        if plugin.name in self._plugins:
            return self
        self._plugins[plugin.name] = plugin
        plugin.install(self)   # 插件可访问 kernel，注册中间件
        return self
```

#### 4. 编写实战插件：安全审查与任务级上下文注入

下面我们编写两个典型的工业级插件（对应 `litecode/security/plugin.py` 的真实实现）：

**插件 A：高危 Tool 审计拦截插件**

```python
# plugins/security_guard_plugin.py
class SecurityGuardPlugin(Plugin):
    name = "security-guard"

    def install(self, kernel: Kernel) -> None:
        @kernel.before_tool.use
        async def _guard(ctx, tool_call, next):
            if tool_call["toolName"] == "execute_command":
                cmd = tool_call["args"].get("command", "")
                DANGEROUS = ["rm -rf /", "drop database", "git push --force", "> /dev/sda"]
                for keyword in DANGEROUS:
                    if keyword in cmd:
                        print(f"[Security Guard Alert]: 拦截高危命令: {cmd}")
                        tool_call["cancel"] = True
                        tool_call["reason"] = f"[Security Error]: 命令包含黑名单操作 \"{keyword}\""
                        return tool_call     # 阻断，不继续向下
            return await next(tool_call)     # 放行，继续下一个中间件
```

**插件 B：任务级上下文注入插件**

```python
# plugins/context_enricher_plugin.py
class ContextEnricherPlugin(Plugin):
    name = "context-enricher"

    def install(self, kernel: Kernel) -> None:
        @kernel.before_llm.use
        async def _enrich(ctx, messages, next):
            # 注入任务内稳定的工作区信息；时间、Git 状态等动态数据由工具查询
            env_prompt = f"\n[System Info]: Project: {__import__('os').getcwd()}"
            updated = list(messages)
            if updated and updated[0].role == "system":
                updated[0] = Message(role="system",
                                     content=updated[0].content + env_prompt)
            return await next(updated)
```

#### 5. 组装与运行效果

```python
# main.py
kernel = Kernel("demo")
kernel.use(SecurityGuardPlugin()).use(ContextEnricherPlugin())

# 模拟触发 beforeLLM 中间件链
messages = [
    Message(role="system", content="You are an AI coding assistant."),
    Message(role="user", content="Help me analyze this code."),
]
messages = await kernel.before_llm.run(kernel.get_context(), messages)
print("Enriched System Prompt:\n", messages[0].content)

# 模拟触发 Tool 安全拦截
dangerous = {"toolName": "execute_command", "args": {"command": "rm -rf /"},
             "cancel": False, "reason": ""}
result = await kernel.before_tool.run(kernel.get_context(), dangerous)
if result.get("cancel"):
    print("Tool execution prevented:", result["reason"])
else:
    print("Tool executed successfully.")
```
