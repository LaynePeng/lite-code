# 第 22 课：会话管理与综合设置——孤儿会话、项目切换、配置面板

## 本课定位

`lite-code` 支持多项目、多会话：用户可以同时打开多个项目，每个项目有自己的会话历史；可以热切换工作区；可以在设置弹窗里管理全局配置。本课围绕"会话"这个核心概念，解决三个真实问题：

1. **孤儿会话**：项目目录被删除后，其会话历史变成"孤儿"，列表里残留一堆点开就打不开的项；
2. **项目切换**：双击历史会话应该能切回对应项目（而不是必须在当前项目里手动找）；
3. **综合设置**：会话清理、zip 上限、MCP 配置等散落的全局项，需要一个统一的设置面板。

## 一、会话与项目绑定回顾（L14 SessionStore）

第 14 课实现了 `SessionStore`：会话以 JSON 文件落盘，每个会话有 `session_id`、`messages`、`metadata`。**本课的关键扩展是 `metadata.workspace`**——会话在创建时记录它属于哪个项目：

```python
# server/app.py（核心）
@fast_app.post("/api/sessions")
async def create_session(payload, request):
    _check_auth(request)
    _require_workspace()

    session_id = f"session_{uuid.uuid4().hex}"   # UUID 防碰撞（见 L24 踩坑）
    metadata: Dict[str, Any] = {}
    if payload.name:
        metadata["name"] = payload.name
    workspace = payload.workspace or app.workspace
    if workspace:
        metadata["workspace"] = workspace        # ← 会话绑定项目
    app.session_store.save(session_id, [], metadata)
    return {"session_id": session_id}
```

**为什么 metadata 里要存 workspace？** 因为 `lite-code` 是"窗口 = 项目 = Core"模型（第 23 课 Electron 篇）：每个窗口绑定一个项目，但会话历史是**按项目隔离**存储的。没有 `metadata.workspace`，会话列表就不知道"这条会话属于哪个项目"，无法过滤也无法切换。

## 二、孤儿会话治理

### 2.1 问题

用户删除了某个项目目录（比如临时克隆的仓库用完就删了）。但它的会话 JSON 文件还留在 `.lite-code/sessions/` 里。于是会话列表出现一条"幽灵会话"——点开它，`metadata.workspace` 指向的目录已经不存在，文件树、git 状态全部失效。

更糟的是**语义错位**：会话列表只显示当前项目的会话（按 workspace 过滤），但孤儿会话的 workspace 指向的目录虽然没了，过滤条件依然匹配（字符串相等），于是"不属于任何现存项目的会话"混进了列表。

### 2.2 列表不显示孤儿

`/api/sessions` 列表接口做两层过滤：

```python
# server/app.py（核心）
@fast_app.get("/api/sessions")
async def list_sessions(request, workspace: str = ""):
    _check_auth(request)
    snapshots = app.session_store.list()
    result = []
    for s in snapshots:
        s_ws = (s.get("metadata") or {}).get("workspace", "")
        if not s_ws:
            continue                        # 无 workspace 绑定的旧会话不显示
        if not os.path.isdir(s_ws):
            continue                        # 项目目录已不存在 → 不显示（孤儿）
        if workspace and os.path.abspath(s_ws) != os.path.abspath(workspace):
            continue                        # 只显示当前项目的会话
        messages = s.get("messages", [])
        if not any(m.get("role") == "user" for m in messages):
            continue                        # 空会话（无用户消息）不显示
        result.append({...})
    return result
```

三个过滤条件：**① 必须绑定 workspace；② 项目目录必须存在；③ 必须有用户消息**。第 2 条就是"孤儿会话不出现在列表"的实现——它不需要真的删除数据，只是在展示层隐藏。

> **设计取舍**：列表接口必须是**纯读取**（不删数据）。因为"创建会话"和"用户发第一条消息"之间存在短暂空窗，如果在列表接口里顺手删孤儿，可能误删正在初始化的会话。所以展示层隐藏 + 显式清理按钮（见下）。

### 2.3 批量清理：DELETE /api/sessions/cleanup

隐藏只是眼不见为净，磁盘上还有残留。提供显式的清理端点：

```python
# server/app.py（核心）
@fast_app.delete("/api/sessions/cleanup")
async def cleanup_sessions(request):
    """一键清理孤儿会话：删除所有关联项目目录已不存在的会话。"""
    _check_auth(request)
    snapshots = app.session_store.list()
    deleted = 0
    for s in snapshots:
        s_ws = (s.get("metadata") or {}).get("workspace", "")
        if not s_ws:
            continue
        if not os.path.isdir(s_ws):
            sid = s.get("session_id", "")
            if not sid:
                continue
            app.session_store.delete(sid)      # 删除会话 JSON
            deleted += 1
            # 附带清理该会话的 TODO 看板（内存 + 磁盘）
            try:
                app.todo_plugin.delete_board(sid)
            except Exception:
                pass
    return {"ok": True, "deleted": deleted}
```

注意它**附带清理 TODO 看板**（第 20 课）：会话删了，会话的 TODO 看板也得删，否则 `todo_boards/` 里残留孤立文件。

## 三、双击会话切项目

### 3.1 场景

用户 A 项目里有会话"重构登录模块"，B 项目里有会话"修复支付流程"。当前窗口停在 A 项目，用户想快速查看 B 项目的那个会话——**双击它，窗口应该自动切到 B 项目并打开该会话**。

### 3.2 前端读取 metadata.workspace

`App.tsx` 处理会话双击：

```typescript
// App.tsx（核心）
const onSessionDoubleClick = async (sessionId: string) => {
  const info = await api.session(sessionId);          // GET /api/sessions/{id}
  const targetWs = (info?.metadata?.workspace as string) || "";
  if (!targetWs) return;
  if (targetWs === currentWorkspace) {
    openChatTab(sessionId);                            // 同项目 → 直接打开
  } else {
    await api.setWorkspace({ path: targetWs });        // POST /api/workspace
    // 切换成功后重新加载会话列表，并打开目标会话
    await refreshSessions();
    openChatTab(sessionId);
  }
};
```

### 3.3 后端热切换

`POST /api/workspace` 由当前 Core 热切换工作目录（不重启进程，见第 23 课）：

```python
# server/app.py（核心）
@fast_app.post("/api/workspace")
async def set_workspace(payload, request):
    _check_auth(request)
    # 有任务运行时返回 409，避免执行中改变文件根目录
    if app.task_manager.running_count() > 0:
        raise HTTPException(status_code=409, detail="有任务运行中，请等待任务结束后切换")
    app.workspace = os.path.abspath(payload.path)
    ...
    return {"ok": True, "workspace": app.workspace}
```

**为什么切项目要重开会话？** 切换 workspace 后，工具实例、文件树、git 状态都指向新目录。旧会话属于旧项目，不能混在新项目里显示——所以前端切完项目后**重新拉取会话列表**（只显示新项目的），再打开目标会话。

## 四、设置弹窗「综合设置」Tab

### 4.1 为什么需要综合设置

设置弹窗（`SettingsModal`）已经有「LLM」和「MCP Server」两个 Tab（第 21 课）。但还有两类散落的全局配置没有入口：

- **会话清理**：一键删除孤儿会话（对应 2.3 的 `DELETE /api/sessions/cleanup`）；
- **zip 上限**：Skills 技能包解压的大小限制（第 8 课权限治理里提到"zip 上限配置"）。

### 4.2 「综合设置」Tab

```
┌─ 设置 ─────────────────────────────────┐
│ [LLM] [MCP Server] [综合设置]          │
│                                        │
│ ┌ 会话管理 ──────────────────────────┐ │
│ │ 孤儿会话（项目已删除的会话）        │ │
│ │ [清理孤儿会话]  ← 调 cleanup 端点   │ │
│ └────────────────────────────────────┘ │
│ ┌ 安全 ──────────────────────────────┐ │
│ │ Skills zip 解压上限： [50 MB]      │ │
│ └────────────────────────────────────┘ │
│                    [保存]             │
└────────────────────────────────────────┘
```

会话清理按钮调用 `api.cleanupSessions()`，返回 `{deleted: N}` 后提示"已清理 N 个孤儿会话"。zip 上限通过 `/api/config` 保存（走后端配置热加载，改完即生效）。

## 五、MCP 保存后工具列表自动刷新

### 5.1 场景

用户在设置弹窗里新增了一个 MCP Server（如 sqlite），保存后：`POST /api/mcp` 落盘配置 → 断开旧连接 → 按新配置重连 → 新工具以 `mcp_<server>_<tool>` 名称注册。但前端**右侧「工具」面板**（ToolPanel）还显示旧的工具列表——需要刷新。

### 5.2 实现

前端在 MCP 保存成功后，重新拉取工具列表：

```typescript
// SettingsModal.tsx（核心）
const onSaveMcp = async (servers) => {
  const res = await api.saveMcp(servers);      // POST /api/mcp
  if (res.ok) {
    // 通知 App 刷新工具列表（MCP 工具从下一个任务开始生效）
    onMcpSaved?.();
  }
};
```

`App.tsx` 收到 `onMcpSaved` 后刷新工具列表 + 重新拉取 MCP 状态：

```typescript
const refreshMcp = useCallback(async () => {
  setMcpState(await api.mcpStatus());
  setTools(await api.tools());   // GET /api/tools → 新工具已注册
}, []);
```

> **注意**：MCP 新工具从**下一个任务**开始生效（每个任务的 `ToolRegistry` 在装配时从 `MCPManager` 快照注册）。所以刷新工具列表只是让用户"看到"新工具存在，正在运行的任务不受影响。

## 本课小结

1. **会话与项目绑定**：`metadata.workspace` 在创建会话时记录项目路径，是会话过滤与切换的基础；
2. **孤儿会话治理**：列表接口隐藏（`os.path.isdir` 检查）+ `DELETE /api/sessions/cleanup` 显式清理（附带 TODO 看板清理）；
3. **双击会话切项目**：读取 `metadata.workspace` → `POST /api/workspace` 热切换 → 重拉会话列表并打开目标会话；
4. **综合设置 Tab**：会话清理按钮 + zip 上限配置，统一走 `/api/config` 热加载；
5. **MCP 保存后刷新**：`onMcpSaved` 回调 → 刷新工具列表与 MCP 状态，新工具从下个任务生效。
